# Пайплайны исправлений

Пользовательская проверка элементов может объявить именованные пайплайны исправлений. Каждый пайплайн появляется в отчёте как доступное исправление. Шаги выполняются сверху вниз внутри Revit-транзакции, открытой панелью отчёта.

```yaml
fixes:
  - name: "Удалить"
    steps:
      - type: "Delete"
        elementSets: ["Target"]
  - name: "Отметить проверенным"
    steps:
      - type: "SetParameter"
        parameter: "ALL_MODEL_INSTANCE_COMMENTS"
        value: "'checked ' + now('dd.MM.yyyy')"
```

`name` обязателен и не может быть пустым. `steps` — обязательная непустая последовательность. Если `fixes` не указан, у проверки не будет исправлений из конфигурации.

`elementSets` выбирает именованные группы элементов для шага:

- `Target` — элемент, для которого сформирован результат проверки;
- `Dependencies` — связанные элементы результата.

Для безопасности отсутствие или пустой список `elementSets` означает только `Target`. Неизвестное имя группы останавливает исправление и откатывает его транзакцию. Чтобы удалить обе стороны результата наподобие коллизии, явно укажите `elementSets: ["Target", "Dependencies"]`.

## Шаги

| `type` | Действие |
| --- | --- |
| `SetParameter` | Записывает одно значение параметра для каждого элемента, выбранного через `elementSets`. |
| `Delete` | Удаляет элементы, выбранные через `elementSets`, и все элементы, которые Revit считает полностью зависимыми от них. Revit не показывает подтверждение и может удалить закреплённый элемент. |

`Delete` — терминальный шаг, он должен быть последним. Перед ним разрешён шаг `SetParameter`, и в пайплайне их может быть несколько. Если шаг завершился ошибкой, объемлющая транзакция не фиксируется. Команда «исправить все» сохраняет успешные исправления других результатов и сообщает об отдельных ошибках.

## SetParameter

`parameter` задаёт параметр самого элемента:

1. имя `BuiltInParameter`, например `ALL_MODEL_INSTANCE_COMMENTS`;
2. GUID общего параметра;
3. отображаемое имя параметра. Отображаемое имя зависит от языка интерфейса, поэтому предпочитайте первые два способа.

`value` — формула в грамматике элемента, той же, что используется в `check`: `parameter(me, '…')`, `property('…')`, `if(…)`, строковые функции и арифметика.

Результат формулы преобразуется в тип хранения параметра:

| Результат | Тип хранения | Как записывается |
| --- | --- | --- |
| строка | `String` | как есть |
| число | `Double` | в проектной единице параметра |
| число | `Integer` | с округлением от нуля |
| число | Yes/No `Integer` | `0` или `1` |
| `true` / `false` | Yes/No `Integer` | `0` или `1` |
| число | `String` | в инвариантной культуре, так же как `str(…)` |
| `ElementId` | `ElementId` | только элемент, существующий в том же документе |

Отсутствующий параметр, параметр только для чтения, пустое значение и несовместимый тип значения оставляют параметр без изменений: шаг сообщает о неудаче, в лог пишутся элемент и причина, а объемлющая транзакция не фиксируется. Формула, которая не компилируется, отклоняет исправление при загрузке конфигурации; сама проверка остаётся активной, а ошибка конфигурации называет исправление и шаг.

> [!warning]
> Числа записываются в проектных единицах параметра: `value: "3000"` — это 3000 миллиметров в метрическом проекте и 3000 метров в проекте с метрами. Результат `property(…)` — сырое значение Revit API во внутренних единицах (футы для длин, радианы для углов), поэтому не смешивайте его с `parameter(…)` в одном выражении.

> [!note]
> Если находка — тип элемента, шаг записывает параметр типа, поэтому меняются все экземпляры этого типа; в лог пишется предупреждение.

> [!note]
> Кнопка с лампочкой сразу запускает единственное доступное исправление. Если исправлений несколько, она открывает меню выбора. Это поведение совпадает с кнопкой визуализации с глазом.

> [!note]
> Команда «исправить все» обрабатывает все результаты с тем же кодом проверки, а не только видимые после фильтрации строки. Успешные изменения сохраняются, даже если другой результат завершился ошибкой; повторная попытка пропускает уже исправленные или недействительные элементы.
