# Теги диагностик

Тег — обычная строка, привязанная к проверке. Теги называют проверку и помогают её найти; на то, как она выполняется, они не влияют. Они показываются в столбце **Теги** панели [[Панель диагностики|проверок]] и панели [[Панель результатов диагностики|результатов]], участвуют в поиске на обеих панелях, по клику подставляются в поиск и попадают в каждый экспортируемый отчёт.

Теги бывают двух видов.

## Пользовательские теги

Их пишет автор правила в списке `tags` файла конфигурации, и они сохраняются как есть. У правила без `tags` их нет. Используйте их для своих соглашений, например раздела или системы.

## Системные теги

Их ставит продукт. Они всегда английские и одинаковые во всех языках интерфейса. Пользовательский тег с именем системного игнорируется, поэтому файл конфигурации не может подделать системный тег.

| Тег | Значение |
| :--- | :--- |
| `BuiltIn` | Проверка входит в состав Revit Linter. |
| `Custom` | Пользовательская проверка из `diagnostics.config.yaml`. |
| `Collision` | Проверка коллизий из `diagnostics.config.yaml`. |
| `ParameterProject` | Проверка параметров проекта из `diagnostics.config.yaml`. |
| `Example` | Проверка из установленных примеров конфигурации. |
| `Tour` | Управляемая учебная проверка практического обучения. |
| `Debug` | Проверка из отладочной конфигурации. |

`Project` и `Family` — это области применения проверки (тип документа). У встроенной проверки их ставит продукт по её фильтру документа; у правила из конфигурации это обычные теги, которые пишет автор в `tags`, потому что только правило знает, где оно работает. Они не зарезервированы.

## Как складывается список тегов проверки

- Встроенная проверка получает `BuiltIn` и области применения (`Project`, `Family` или обе).
- Правило, загруженное из файла конфигурации, получает тег своего объявленного `type` (`Custom`, `Collision` или `ParameterProject`) и, если правило установил продукт, тег происхождения (`Example`, `Tour` или `Debug`). Затем идут теги `tags` из файла.
- Системные теги идут первыми в порядке объявления, затем пользовательские — в порядке записи в файле.

Перед сборкой списка теги обрезаются от пробелов, пустые теги отбрасываются, а дубликаты схлопываются без учёта регистра: `MEP` и `mep` — один тег.
