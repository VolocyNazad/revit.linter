> Язык: [[User diagnostics|English]] · **Русский**

Список проверок и их поведение задаются в едином [[Файл конфигурации|файле конфигурации]] `diagnostics.config.yaml`. Пользовательская проверка элементов — это правило с `type: "custom"`; файл должен находиться в [[Размещение файлов конфигурации|папке конфигурации]] соответствующей версии Revit.

Готовый пример: [diagnostics.config.yaml](../../../examples/configuration/ru/diagnostics.config.yaml).

---

**Пример конфигурации:**
```yml
- type: "custom"
  code: "CSTM001"
  description: "custom"
  message: "For the element named '{elementName}' with identifier '{elementId}', the 'Марка' and/or 'Комментарии' parameters are incorrectly set. Execution time '{duration}' ms."
  isObsolete: true
  takeDocument: "!property('IsFamilyDocument')"
  take: "instance and builtincategory('OST_Walls')"
  check: "parameter(me, 'Комментарии') == 'Ура!' & parameter(me, 'Марка') == 'Ура!'"
- code: "CSTM002"
  description: "custom"
  message: "For the element named '{elementName}' with identifier '{elementId}', the name is incorrectly set"
  severity: "Message"
  isActive: false
  isObsolete: true
  obsoleteDescription: "Some text describing the reason the check is obsolete"
  takeDocument: "true"
  take: "instance and builtincategory('OST_Walls')"
  check: "property('Name') == '1'"
  tags: ["Стены", "Именование"]
- code: "CSTM003"
  ...
```

---

**Параметры:**

| Поле                  | Тип                | Тип входных данных | Тип возвращаемого значения формулы | Назначение                                                                                                     |
| --------------------- | ------------------ | ------------------ | ---------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `type`                | строка             | `string`           | `-`                                | Тип правила; для пользовательской проверки элемента должен быть `custom` |
| `code`                | строка             | `string`           | `-`                                | Уникальный идентификатор проверки                                                                              |
| `description`         | строка             | `string`           | `-`                                | Описание проверки                                                                                              |
| `message`             | строка             | `string`           | `-`                                | Шаблон сообщения об ошибке. Доступные переменные: `{elementName}`, `{elementId}`, `{duration}` (по умолчанию: локализованный общий шаблон) (необязательно) |
| `severity`            | перечисление       | `string`           | `-`                                | [[Уровни важности]] <br>(по умолчанию: `Message`) (необязательно)                                              |
| `isActive`            | логический         | `bool`             | `-`                                | Активна ли проверка (по умолчанию: `true`) (необязательно)                                                     |
| `isHidden`            | логический | `bool`              | `-`                                | Скрывает проверку с панелей, из списка запуска и отчётов и останавливает её выполнение (по умолчанию: `false`) (необязательно) |
| `isObsolete`          | логический         | `bool`             | `-`                                | [[Устаревшие проверки]] (по умолчанию: `false`) (необязательно)                                                |
| `obsoleteDescription` | строка             | `string`           | `-`                                | [[Устаревшие проверки]] (отображается, когда `isObsolete: true`) (необязательно)                               |
| `takeDocument`        | строка             | `string`           | `bool`                             | [[Синтаксис формул\|Формула фильтрации документов]]                                                           |
| `take`                | строка             | `string`           | `ElementFilter`                    | [[Объекты Revit в формулах\|Формула отбора элементов]]                                                        |
| `check`               | строка             | `string`           | `bool`                             | [[Синтаксис формул\|Формула проверки элемента]]. Если результат равен `true`, элемент считается прошедшим проверку |
| `fixes`               | последовательность | `-`                | `-`                                | Необязательные [[Пайплайны исправлений]], доступные для непрошедших проверку элементов.                        |
| `tags`                | последовательность строк | `string`      | `-`                                | Теги для поиска проверки на панелях; показываются в отчётах (по умолчанию: нет) (необязательно)                |


---

**Примечания:**
- Если поле `message` не указано, по умолчанию используется локализованный общий шаблон.
- Если поле `severity` не указано, по умолчанию оно равно `Message`.
- Если поле `isActive` не указано, по умолчанию оно равно `true`.
- Если поле `isObsolete` не указано, по умолчанию оно равно `false`.
- Теги — свободный текст; поиск и сопоставление тегов не учитывают регистр. Теги области применения `Project` (выполняется в документах проекта) и `Family` (выполняется в семействах) — обычные теги, которые правило указывает в `tags`; зарезервированные теги продукта описаны в статье [[Теги диагностик]].

> **Примечание:** если `diagnostics.config.yaml` не удалось разобрать, список пользовательских проверок считается пустым, а ранее загруженные правила не сохраняются. Revit Linter показывает ошибку конфигурации в интерфейсе и записывает исключение вместе с путём к файлу в журнал приложения.

> **Примечание:** если формулу `takeDocument`, `take` или `check` не удалось скомпилировать, соответствующий этап правила не выполняется. Предупреждение в журнале приложения содержит текст отклонённой формулы, чтобы можно было определить проблемное выражение.
