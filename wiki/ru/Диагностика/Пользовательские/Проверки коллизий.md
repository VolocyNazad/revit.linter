> Язык: [[Collision diagnostics|English]] · **Русский**

Список проверок и их поведение задаются в едином [[Файл конфигурации|файле конфигурации]] `diagnostics.config.yaml`. Проверка коллизий — это правило с `type: "collision"`; файл должен находиться в [[Размещение файлов конфигурации|папке конфигурации]] соответствующей версии Revit.

Готовый пример: [diagnostics.config.yaml](../../../examples/configuration/ru/diagnostics.config.yaml).

| --------------------- | --------------- | ------------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `description`         | строка          | `string`            | `-`                              | Описание проверки                                                                                                                                        |
| `message`             | строка          | `string`            | `-`                              | Шаблон сообщения об ошибке. Находка перечисляет все элементы, с которыми пересекается целевой: `{intersection.elementNames}` и `{intersection.elementIds}` — списки через запятую в одинаковом порядке, `{intersection.count}` — их количество (по умолчанию: локализованный общий шаблон) (необязательно) |

| `andTake`             | строка          | `string`            | `ElementFilter`                  | [[Объекты Revit в формулах\|Формула отбора второй группы элементов]], с которой проверяются пересечения                                                      |

## Связанные модели, соединённые элементы и вложенные семейства

- Связи участвуют только если правило задаёт `includeLinks: true` (по умолчанию `false`), поэтому существующие конфигурации работают как раньше.
- Участвуют все загруженные связи; выбора отдельных связей нет. Поддерживаются только прямые связи, незагруженные пропускаются с предупреждением, а замечания остаются на элементах хоста: пары «связь против связи» никогда не проверяются.
- Попадания по связям остаются в отчёте только текстом: они не входят в список зависимостей, поэтому визуализации подсвечивают только целевой элемент хоста, а исправления действуют только на хост. Имена элементов связей выглядят как `Имя [Связь]` в `{intersection.elementNames}`.
- Связь с неконформной трансформацией проверяется только по ограничивающим параллелепипедам, без проверки тел.
- `ignoreConnectedElements: true` пропускает элементы, соединённые с целевым коннекторами MEP: они стыкуются по проекту, а их геометрия семейств пересекается в месте стыка. Пара, которая реально пересекается ещё где-то, тоже пропускается. Флаг действует только на пары внутри хост-документа: коннекторы не соединяют элементы через Revit-связи.
- `ignoreNestedFamilies: true` пропускает пару, элементы которой сводятся к одному верхнему экземпляру семейства: родитель и его вложенное семейство, вложенные семейства одного родителя и любая пара глубже в том же дереве. Их пересечение решается внутри семейства, поэтому пара пропускается, даже если она реально пересекается. Связь берётся из `FamilyInstance.SuperComponent`, а не из формул, поэтому она сохраняется и тогда, когда родитель не выбран правилом. Отдельными элементами проекта становятся только вложенные семейства с включённым признаком «Общий» (Shared); необщее вложенное семейство остаётся частью геометрии родителя и никогда не участвует в проверке как самостоятельный элемент, поэтому флаг меняет результат именно для общих вложенных семейств. Флаг убирает только пары внутри семейства: вложенная деталь по-прежнему проверяется против всего остального, а третий элемент, пересекающий вложенную деталь, может прийти в отчёте и на деталь, и на её родителя. Флаг действует только на пары внутри хост-документа и почти ничего не меняет в документе семейства, где у верхнего вложенного компонента нет родительского элемента. Чтобы флаг дал видимый эффект, вложенная деталь должна проходить `take`/`andTake`.

**Примечания:**
- Если поле `message` не указано, по умолчанию используется локализованный общий шаблон.
- Если поле `severity` не указано, по умолчанию оно равно `Message`.
- Если поле `isActive` не указано, по умолчанию оно равно `true`.
- Если поле `isObsolete` не указано, по умолчанию оно равно `false`.
- Если поле `includeLinks` не указано, по умолчанию оно равно `false`: связи участвуют только при явном включении, а попадания по ним остаются в отчёте только текстом.
- Если поле `ignoreConnectedElements` не указано, по умолчанию оно равно `false`. Установите `true`, чтобы пропускать соединённые элементы: они стыкуются по проекту, а их геометрия семейств пересекается в месте стыка и иначе считалась бы коллизией. Пара, которая реально пересекается ещё где-то, тоже пропускается. Флаг действует только на пары внутри хост-документа: коннекторы не соединяют элементы через Revit-связи.
- Если поле `ignoreNestedFamilies` не указано, по умолчанию оно равно `false`. Установите `true`, чтобы пропускать пары внутри одного размещённого семейства: родитель и его вложенное семейство, а также вложенные семейства одного родителя пересекаются по замыслу семейства и иначе считались бы коллизиями. Флаг действует только на пары внутри хост-документа и не убирает дубли по одному третьему элементу; см. раздел выше.
- Теги — свободный текст; поиск и сопоставление тегов не учитывают регистр. Теги области применения `Project` (выполняется в документах проекта) и `Family` (выполняется в семействах) — обычные теги, которые правило указывает в `tags`; зарезервированные теги продукта описаны в статье [[Теги диагностик]].
