# Встроенные проверки и пользовательские правила

Revit Linter может проверять модель двумя взаимодополняющими способами.

| | Встроенные проверки | Пользовательские правила |
|---|---|---|
| Для чего подходят | Типовые проблемы качества модели | Требования проекта и компании |
| Настройка | Не требуется | YAML-файлы в папке конфигурации |
| Кто поддерживает | Обновляются вместе с Revit Linter | Редактируются вашей командой |
| С чего начать | Включить проверку и запустить её | Скопировать пример и изменить одно условие |

## Начните со встроенных проверок

Встроенные проверки готовы к работе сразу. Откройте [[Панель диагностики]], выберите подходящие проверки и запустите их на [[Панель результатов диагностики|панели результатов]]. Это самый короткий путь к полезному отчёту, не требующий знания YAML.

## Добавьте пользовательское правило для собственного требования

Пользовательское правило описывает:

- `code` — постоянный уникальный код;
- `description` — название в интерфейсе;
- `severity` — сообщение, предупреждение или ошибка;
- `take` — какие элементы Revit проверять;
- `check` — условие корректного элемента.

Выражение `check` описывает корректное состояние. Каждый отобранный через `take` элемент, для которого `check` вернул `false`, становится замечанием.

Для первого небольшого примера откройте [[Создание первого правила]]. Полное описание полей, формул, визуализаций и исправлений находится на странице [[Пользовательские проверки]].
