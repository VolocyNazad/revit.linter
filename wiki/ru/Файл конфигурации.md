# Файл конфигурации

Revit Linter читает всю конфигурацию проверок из одного файла на версию Revit:

`Documents\Revit Linter\<year>\diagnostics.config.yaml`

При первом запуске продукт создаёт файл с комментарием-шапкой. После него читаются ещё две копии в таком порядке:

| Расположение | Назначение |
| --- | --- |
| `diagnostics.config.yaml` | Ваши правила и настройки. |
| `debug\diagnostics.config.yaml` | Необязательные отладочные правила. |
| `examples\diagnostics.config.yaml` | Пример конфигурации, установленный окном знакомства. |

Управляемая конфигурация [[Практическое обучение|обучения]] остаётся в `tour\practical-tour.config.yaml`; обучение само её устанавливает и удаляет.

## Структура файла

```yaml
# File format version for compatibility checks.
version: 2
rules:
  - type: custom
    code: "CSTM001"
    ...
```

`version` должен быть равен `2`. Файл с версией новее запущенного продукта игнорируется; файл без поддерживаемой версии игнорируется и об этом сообщается. Старые файлы `config.yaml`, `collision.config.yaml` и `parameter-element.config.yaml` не читаются — см. [[Миграция конфигурации]].

## Типы правил

| `type` | Цель | Назначение |
| --- | --- | --- |
| `custom` | элемент | Ваша проверка элементов. |
| `collision` | элемент | Сравнивает элементы между собой. |
| `parameter` | документ | Проверяет параметры проекта. |
| `builtIn` | элемент или документ | Переопределяет встроенную проверку продукта. |

Поля каждого типа описаны в [[Пользовательские проверки]], [[Проверки коллизий]] и [[Проверки параметров проекта]]. Запись `builtIn` содержит только `code`, `isActive`, `severity` и `isHidden`; остальные поля отклоняются.

## Общие поля

| Поле | Значение |
| --- | --- |
| `code` | Постоянный уникальный идентификатор проверки. |
| `isActive` | Выполняется ли проверка. По умолчанию `true`. |
| `severity` | `Message`, `Warning` или `Error`. По умолчанию `Message`. |
| `isHidden` | Скрывает проверку с панелей, из списка запуска и из отчётов, а также не даёт ей выполняться. По умолчанию `false`. |
| `tags` | Свободные теги для поиска проверки; показываются в отчётах. |

`isHidden` сильнее `isActive`: скрытая проверка не выполняется, даже если `isActive: true`. Отсутствующая запись `builtIn` использует значения по умолчанию из кода.

## Приоритет и конфликты

Правила читаются в порядке источников: пользовательский файл, `debug`, `examples`, затем управляемый файл обучения; внутри файла — сверху вниз. Если два правила одного target имеют одинаковый код, побеждает первое. Пользовательское правило никогда не переопределяет встроенную проверку с тем же кодом и target.

## Редактирование и перезагрузка

Панель **Проверки** записывает изменения, сделанные флажками и списком важности, обратно в `diagnostics.config.yaml`. Меняются только затронутые поля, поэтому комментарии и порядок правил сохраняются. Новая запись встроенной проверки добавляется под маркер `# Built-in overrides` в конце списка.

Revit Linter следит за файлами и перезагружает их после внешнего редактирования. Некорректное правило пропускается и описывается в уведомлении; остальные правила продолжают работать. Файл, который не является корректным YAML, считается пустым, и об этом сообщается.

Кнопка **Открыть конфигурацию** в строке проверки открывает файл, в котором она объявлена. Для встроенных проверок это верхний `diagnostics.config.yaml`.

**Сброс настроек** удаляет все переопределения встроенных проверок и все поля `isHidden`. Он не меняет `isActive` и `severity` ваших собственных правил.
