# Миграция конфигурации

Раньше Revit Linter читал три отдельных файла — `config.yaml`, `collision.config.yaml` и `parameter-element.config.yaml` — а переключатели пользователя хранил в отдельных файлах настроек. Формат конфигурации 2 читает один `diagnostics.config.yaml` на версию Revit и хранит действующие настройки в нём. **Старые файлы не читаются вообще.**

При первом запуске после обновления, до чтения конфигурации, продукт переносит старые файлы каждой папки версии Revit в подпапку `legacy` этой папки. Затем он показывает **одно предупреждение на установленный продукт** — не по одному на каждую версию Revit — если нашёл старые файлы; кнопка предупреждения открывает эту страницу. На панели «Проверки» нет баннера, а уведомления на каждую версию Revit больше нет. Старые файлы продукт никогда не удаляет.

## Где теперь старые файлы

Продукт просматривает все папки версий в `Documents\Revit Linter\<year>\`, а не только запущенную версию Revit, и сохраняет структуру подпапок. Сканируются только папки с именем из четырёх цифр (год выпуска), поэтому копия для резервной копии рядом с ними (например, `2025-backup`) не затрагивается:

| Прежнее расположение | Новое расположение |
| --- | --- |
| `<year>\config.yaml` | `<year>\legacy\config.yaml` |
| `<year>\collision.config.yaml` | `<year>\legacy\collision.config.yaml` |
| `<year>\parameter-element.config.yaml` | `<year>\legacy\parameter-element.config.yaml` |
| копии в `<year>\examples\` | `<year>\legacy\examples\` |
| копии в `<year>\debug\` | `<year>\legacy\debug\` |

Если переносимый файл перезаписал бы существующий файл в папке `legacy`, он получает числовой суффикс, например `config-2.yaml`. Продукт создаёт `<year>\legacy\README.txt` с объяснением, что произошло, и ссылкой на эту страницу. Файл, который не удаётся перенести, например потому что его удерживает другая программа, остаётся на месте и записывается в журнал; предупреждение всё равно появляется, потому что старые файлы найдены.

Больше продукт эти файлы не читает. Правила, переключатели и игнорирования из них не действуют. Старые файлы настроек пользователя `elementDiagnosticSettings.yml` и `documentDiagnosticSettings.yml` в `%LOCALAPPDATA%\Volocy\Revit.Linter\settings\` тоже не переносятся и не читаются, а старые параметры игнорирования в модели `Linter_Ignored` и `Linter_IgnoredType` не читаются.

## Что сделать

Переносите вручную, в таком порядке. Продукт не переносит ни одного правила, переключателя или игнорирования за вас: всё после предупреждения — ваша ответственность. Перед началом скопируйте всю папку конфигурации, например в `2025-backup`. Для Revit 2025 это папка `Documents\Revit Linter\2025\`. Держите копию, пока не убедитесь, что новая конфигурация работает.

1. Откройте папку конфигурации: на панели «Проверки» нажмите [[Кнопка папки конфигурации|Открыть папку конфигураций]] на панели инструментов у правого края. У каждой версии Revit своя папка и свой `diagnostics.config.yaml`.
2. Создайте или откройте `diagnostics.config.yaml` в этой папке. Если файла ещё нет, запустите Revit Linter один раз: продукт создаст его только с обычной шапкой формата, без комментария о миграции. Можно создать файл и вручную.
3. Перенесите правила в список `rules:` файла `diagnostics.config.yaml` и укажите каждому правилу `type` того файла, откуда оно пришло:
   - правилам из `config.yaml` — `type: custom`;
   - правилам из `collision.config.yaml` — `type: collision`;
   - правилам из `parameter-element.config.yaml` — `type: parameter`.

   Остальные поля правил не меняйте:

   ```yaml
   version: 2
   rules:
     - type: custom
       code: "CSTM001"
       description: "Generic model instances"
       takeDocument: "!property('IsFamilyDocument')"
       take: "instance and builtincategory('OST_GenericModel')"
       check: "isnull(property('Id'))"

     - type: collision
       code: "CLSN101"
       ...
   ```

4. Восстановите переключатели, которые хранились в старых файлах настроек:
   - у своих правил задайте `isActive` и `severity` прямо в правиле;
   - для встроенных проверок добавьте записи в конце списка, под `# Built-in overrides`:

   ```yaml
   # Built-in overrides
   - type: builtIn
     code: "SHRD003"
     isActive: false
     severity: "Warning"
   ```

   Старые файлы `elementDiagnosticSettings.yml` и `documentDiagnosticSettings.yml` в `%LOCALAPPDATA%\Volocy\Revit.Linter\settings\` автоматически не переносятся. Они остаются на диске для отката; значения, которые ещё нужны, перенесите в записи выше вручную.
5. Заново проигнорируйте замечания, которые нужно оставить проигнорированными. Прежний список игнорирования из 2.0.0, включая параметры игнорирования в модели, не переносится, поэтому ранее проигнорированные находки снова появятся. Добавьте их снова через меню лампочки или панель [[Панель игнорирования|Игнорирования]].
6. Если вы устанавливали примеры, переустановите их из **Начало работы**. Окно знакомства снова предлагает шаг с примерами и записывает новый `examples\diagnostics.config.yaml`; существующий файл примера, отличающийся от поставляемого, перед этим копируется в `.bak-<timestamp>`, а идентичный файл не затрагивается. Устаревшие копии примеров установщик больше не обрабатывает: их уже перенесла миграция при запуске в `<year>\legacy\examples\`.
7. Сохраните файл и дождитесь перезагрузки. Панель «Проверки» покажет новый список. Убедитесь, что нужные правила на месте, а пропущенное правило описано в уведомлении, затем исправьте правило и сохраните файл снова.
8. Только после того, как новая конфигурация заработает, наведите порядок. Папки `legacy` продукт оставляет и никогда не удаляет; удалить их — ваше решение, и оно необратимо. Держите их, пока не убедитесь в результате: это единственная оставшаяся копия старых правил и единственный путь назад к старой версии продукта. Старые файлы настроек в `%LOCALAPPDATA%\Volocy\Revit.Linter\settings\` можно удалить тогда же.

## Один файл — одна зона отказа

Теперь все правила лежат в одном файле, поэтому одна ошибка YAML или неверный `version` отключает сразу все правила в `diagnostics.config.yaml`. Держите копию папки, сделанную перед шагами, чтобы быстро вернуть последний рабочий файл.

## Визуализация по умолчанию

Перенесённое правило без `visualizations` теперь получает текущий пайплайн по умолчанию — **Показать и выбрать**. В прежнем формате по умолчанию был **Показать**. Если нужно прежнее поведение, укажите визуализацию в правиле явно.

## Практическое обучение

Управляемый файл `tour\practical-tour.config.yaml` устанавливает сам продукт. Устаревшая копия старого формата обновляется автоматически при запуске: действие пользователя и диалог ошибки не нужны. При запуске обучения текущий формат устанавливается заново. Переносить этот файл не нужно.

## Если что-то пропущено

Уведомление начинается с имени файла и кода правила, например:

`diagnostics.config.yaml: rule 'CLSN101' was skipped: поле andTake не указано`

Префикс `diagnostics.config.yaml: rule '...' was skipped:` не переводится, переводится только причина. Исправьте правило и сохраните файл снова. Файл с `version`, отличным от `2`, сообщается целиком и игнорируется. Файл, который не является корректным YAML, считается пустым.

## Откат

Старые файлы перенесены, а не удалены, но в корне папки версии их больше нет. Чтобы вернуться на старую версию продукта, сначала верните их из `<year>\legacy\` на прежние места: файлы верхнего уровня — в `<year>\`, копии из `legacy\examples\` — в `examples\`, копии из `legacy\debug\` — в `debug\`. Если перенесённый файл получил числовой суффикс, переименуйте его в исходное имя. Только после этого переустанавливайте старую версию продукта: пока файлы не возвращены, она не увидит свою конфигурацию.

Ничего не удалено, поэтому данные восстановимы. Старые файлы настроек не изменялись и снова читаются старой версией, а старые параметры игнорирования остаются в модели. Управляемый файл обучения обновлён до текущего формата, поэтому старая версия может заменить его снова.
