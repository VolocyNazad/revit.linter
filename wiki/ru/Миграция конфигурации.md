# Миграция конфигурации

Раньше Revit Linter читал три отдельных файла — `config.yaml`, `collision.config.yaml` и `parameter-element.config.yaml` — плюс пользовательские настройки переопределений. Версия 2 читает один `diagnostics.config.yaml` на версию Revit и хранит действующие настройки в нём. **Старые файлы не читаются вообще.** Они остаются без изменений, поэтому при необходимости можно вернуться на старую версию продукта.

Продукт один раз на версию Revit показывает уведомление о миграции, если находит старый файл. В уведомлении есть кнопка, открывающая эту страницу.

## Что сделать

1. Откройте папку конфигурации: вкладка **Проверки** → **Открыть папку конфигурации**. Для Revit 2025 это `Documents\Revit Linter\2025\`.
2. Если `diagnostics.config.yaml` ещё нет, запустите Revit Linter один раз: файл создастся с шапкой. Можно создать его и вручную.
3. Перенесите правила из старых файлов в `diagnostics.config.yaml`:
   - правилам из `config.yaml` добавьте `type: custom`;
   - правилам из `collision.config.yaml` — `type: collision`;
   - правилам из `parameter-element.config.yaml` — `type: parameter`.

   Остальные поля правил не меняйте:

   ```yaml
   version: 2
   rules:
     - type: custom
       code: "CSTM001"
       description: "Generic model instances"
       takeDocument: "!property('IsFamilyDocument')"
       take: "instance and builtincategory('OST_GenericModel')"
       check: "isnull(property('Id'))"

     - type: collision
       code: "CLSN101"
       ...
   ```

4. Восстановите переключатели, которые были в панели **Проверки**:
   - у своих правил задайте `isActive` и `severity` прямо в правиле;
   - для встроенных проверок добавьте записи в конце списка, под `# Built-in overrides`:

   ```yaml
   # Built-in overrides
   - type: builtIn
     code: "SHRD003"
     isActive: false
     severity: "Warning"
   ```

   Старые файлы `elementDiagnosticSettings.yml` и `documentDiagnosticSettings.yml` в `%LOCALAPPDATA%\Volocy\Revit.Linter\settings\` больше не читаются. Они сохранены для отката; значения из них можно перенести в записи выше.
5. Сохраните файл и дождитесь перезагрузки. Панель **Проверки** покажет новый список; уведомление об ошибке конфигурации опишет каждое пропущенное правило.
6. При желании удалите старые файлы. Оставлять их безопасно: продукт их не читает.

## Файлы в `examples` и `debug`

То же изменение касается необязательных папок:

- окно знакомства теперь устанавливает `examples\diagnostics.config.yaml` и удаляет устаревшие примеры, которые ставило раньше;
- если вы ведёте свои отладочные правила, перенесите `debug\config.yaml`, `debug\collision.config.yaml` и `debug\parameter-element.config.yaml` в `debug\diagnostics.config.yaml` с теми же `type`.

## Практическое обучение

Управляемый `tour\practical-tour.config.yaml` устанавливается самим обучением и миграции не требует. При запуске обучения файл переустанавливается в текущем формате.

## Если что-то пропущено

Уведомление начинается с имени файла и кода правила, например:

`diagnostics.config.yaml: rule 'CLSN101' was skipped: the andTake field is missing`

Исправьте правило и сохраните файл снова. Файл с `version`, отличным от `2`, сообщается целиком; файл, который не является корректным YAML, считается пустым.

## Откат

Старые файлы и настройки не изменяются. Чтобы вернуться на старую версию продукта, установите её снова: она снова будет читать свои файлы и настройки.
