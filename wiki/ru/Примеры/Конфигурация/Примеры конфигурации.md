Файл рядом с английской версией этой страницы — рабочий пример конфигурации, который хранится вместе с документацией. Revit Linter не считывает его из репозитория: этот же файл устанавливает [[Кнопка начала работы|окно знакомства]], либо его можно скопировать вручную.

| Файл | Содержимое |
| --- | --- |
| [`diagnostics.config.yaml`](../../../examples/configuration/ru/diagnostics.config.yaml) | Единый файл конфигурации: шесть проверок элементов (`type: custom`), одиннадцать правил коллизий (`type: collision`) и три правила параметров проекта (`type: parameter`). У первой проверки элементов, `CSTM001`, есть настроенное исправление: оно заполняет пустой параметр «Комментарии». В инженерных системах (`CLSN1xx`) есть варианты только хоста, связанных моделей (`CLSN104`) и соединённых участков (`CLSN105`); далее идут архитектура (`CLSN2xx`) и конструкции (`CLSN3xx`). Каждое правило коллизий задаёт `ignoreNestedFamilies: true`, поэтому пары внутри одного размещённого семейства не попадают в отчёт. |
| [`practical-tour.config.yaml`](../../../examples/configuration/ru/practical-tour.config.yaml) | Управляемое правило коллизий `TOUR001` со всеми визуализациями и меню исправлений, которые нужны сценарию. Устанавливается автоматически при запуске обучения. |

Ссылки ведут на файл с русскими текстами сообщений; тот же файл с английскими текстами лежит [уровнем выше](../../../examples/configuration/diagnostics.config.yaml). В формулах параметры заданы именами `BuiltInParameter`, поэтому правила работают в Revit на любом языке.

## Проверки, сгенерированные из шаблонов ADSK

В папке [`template-checks`](../../../examples/template-checks) лежат два выпуска одних и тех же блоков проверок, сгенерированных из шаблонов ADSK для Revit 2021. В блоках в корневых папках `en/` и `ru/` используется запись групп параметров `PG_*` версий Revit 2021–2023; блоки в `2024/en/` и `2024/ru/` — те же правила со значениями групп Revit 2024 и новее, записанными строками ForgeTypeId, например `autodesk.parameter.group:data-1.0.0`. Каждый блок содержит одно правило параметров проекта и по одной проверке заполнения для каждого параметра типа «Текст» или «Многострочный текст», привязанного к категориям элементов.

Правило `type: parameter` требует, чтобы параметры проекта из шаблона его раздела сохраняли имя, GUID общего параметра, тип привязки, группу параметров, список категорий и признак изменения по группам.

Проверки заполнения — это правила `type: custom` для параметров типа «Текст» и «Многострочный текст» того же шаблона, привязанных к категориям элементов. Правило отбирает элементы этих категорий и проверяет `!isnullorempty(parameter(me, '...'))`: попадание означает, что параметр у элемента пуст. Параметры экземпляра и типа проверяются отдельно — параметр экземпляра отбирается условием `take: instance and (builtincategory(...) or ...)`, параметр типа — `take: type and (builtincategory(...) or ...)`, — поэтому заполненное значение экземпляра не скрывает пустое значение типа и наоборот. Проверки заполнения имеют важность **Message**, а не **Warning**, как у правила параметров проекта.

Код проверки заполнения — `CSTM`, номер блока и трёхзначный индекс, например `CSTM401001` для первой архитектурной проверки. Коды не повторяются между блоками.

| Код | Раздел | Параметров | Проверок заполнения |
| --- | --- | --- | --- |
| `PRMTR401` | Архитектура (АР) | 104 | 81 |
| `PRMTR402` | Водоснабжение (ВК) | 65 | 58 |
| `PRMTR403` | Железобетон (КЖ) | 93 | 72 |
| `PRMTR404` | Металлоконструкции (КМ) | 93 | 69 |
| `PRMTR405` | Отопление и вентиляция (ОВ) | 88 | 68 |
| `PRMTR406` | Слаботочные системы (СС) | 119 | 97 |
| `PRMTR407` | Технология (ТХ) | 61 | 46 |
| `PRMTR408` | Электроснабжение (ЭОМ) | 108 | 93 |
| | **Итого** | **731** | **584** |

Блоки с русскими текстами — в `template-checks/ru/` и `template-checks/2024/ru/`, с английскими — в `template-checks/en/` и `template-checks/2024/en/`. [[Кнопка начала работы|Окно знакомства]] дописывает выбранные блоки в установленный `examples\diagnostics.config.yaml`, поэтому проверки остаются в группе примеров и появляются в списке проверок как обычные правила. Коды и количество в таблице одинаковы в обоих выпусках, проверки заполнения тоже идентичны. Чтобы установить блок вручную, добавьте его под ключ `rules:` своего [[Файл конфигурации|файла конфигурации]] и возьмите выпуск, соответствующий вашей версии Revit: корневые блоки для Revit 2021–2023 и блоки `2024` для Revit 2024–2027.

Окно знакомства предлагает блоки проверок на каждой поддерживаемой версии Revit и само выбирает выпуск: Revit 2021–2023 получает блоки `PG_*`, Revit 2024–2027 — блоки ForgeTypeId. Параметр, у которого в шаблонах 2021 года группа была `INVALID`, в выпуске 2024 года сопоставляется с пустым `group: ""`. Правило выполняется в любом документе-проекте, поэтому устанавливайте только свои разделы — в модели, созданной по шаблону другого раздела, таких параметров нет, и они попадут в отчёт как отсутствующие. Один параметр архитектурного блока, `ADSK_Класс конструктивной пожарной опасности здания`, сопоставляется по имени: в шаблоне у него нулевой GUID общего параметра.

Проверка заполнения сообщает о любом пустом параметре, в том числе о том, который стандарт компании намеренно оставляет необязательным: например, `ADSK_Примечание` или строки штампа (`ADSK_Штамп*`) часто остаются пустыми. Такая проверка будет попадать в отчёт, пока значение не заполнено, поэтому отключите или удалите её из установленного `examples\diagnostics.config.yaml`, если ваш стандарт компании не требует это значение.

## Структура файла

Каждое правило объявляет свой модуль через `type`:

```yaml
version: 2
rules:
  - type: custom
    code: "CSTM001"
    ...
  - type: collision
    code: "CLSN101"
    ...
  - type: parameter
    code: "PRMTR101"
    ...
```

Правила `custom` и `collision` — проверки элементов, `parameter` — проверки документа. Запись `builtIn` переопределяет активность, важность или видимость встроенной проверки и содержит только `code`, `isActive`, `severity` и `isHidden`.

## Блоки разделов

В примере каждый раздел заключён в пару строк-комментариев:

```yaml
# >>> section: mep — Инженерные системы (ИОС)
- type: "collision"
  code: "CLSN101"
  ...
# <<< section: mep
```

Окно знакомства оставляет только блоки выбранных разделов (`mep`, `architecture`, `structure`). При ручном копировании удалите ненужные блоки или оставьте все.

## Что важно учитывать

- Коллизии по умолчанию ищутся внутри одного документа. Связанные модели участвуют, только если правило задаёт `includeLinks: true` (в примере это CLSN104), а попадания по связям остаются в отчёте только текстом. Правило отбирает элементы по категории и классу, поэтому несущую стену от архитектурной оно не отличит. Запускайте блок в модели своего раздела или сузьте его через `takeDocument`.
- В примерах `groupBy` — константа, поэтому каждый отобранный элемент сравнивается с каждым. Замените её формулой, чтобы сравнивать элементы только внутри группы.
- Правила параметров проекта используют имена и GUID из файла общих параметров ADSK. Тип привязки, категории и группа — пример стандарта компании; приведите их к своему шаблону.
- Правила параметров проекта из примера используют формат `group` для Revit 2024 и новее. Для Revit 2021–2023 замените его именем `BuiltInParameterGroup`, например `PG_DATA`: правило, у которого `group` не подходит запущенной версии Revit, пропускается при загрузке файла. Окно знакомства заменяет группу автоматически. Подробнее — [[Проверки параметров проекта]].
- В примерах правил указан список `tags`. Теги — свободный текст: по ним можно найти правило на панелях, и они попадают в экспортируемые отчёты. Каждое правило начинается с тега дисциплины, написанного на языке файла: `Общие`, `Системы`, `Архитектура` и `Конструкции`. Приведите их к своим соглашениям; у правила без `tags` тегов нет. Во встроенных правилах указан `Project`, потому что их `takeDocument` ограничивает их документами-проектами.

## Рабочая конфигурация

Revit Linter считывает рабочий файл `diagnostics.config.yaml` из [[Размещение файлов конфигурации|папки конфигурации]] для текущей версии Revit. Например, Revit 2025 использует:

`C:\Users\{UserName}\Documents\Revit Linter\2025\`

Самый простой способ открыть эту папку — [[Кнопка папки конфигурации]] на панели «Проверки». Чтобы использовать пример вручную, скопируйте его в эту папку как `diagnostics.config.yaml`.

Файлы `examples\diagnostics.config.yaml` и `debug\diagnostics.config.yaml` тоже читаются — после пользовательского. Файл должен объявлять `version: 2`; старые раздельные файлы при запуске переносятся в папку `legacy` и больше не читаются, а файл с версией новее запущенного продукта игнорируется. См. [[Файл конфигурации]] и [[Миграция конфигурации]].
